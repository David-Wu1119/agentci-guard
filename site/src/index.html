      03 / A SMALL CHANGE, A DIFFERENT REVIEW

      Authorization is context.
      It is not content trust.

      Compare three illustrative configurations. The reproduced case below is separate from these examples; this page does not scan your repository.

      UNREVIEWED VERSION

      Keep the write-token finding critical.

      A mutable tag or an unreviewed commit does not establish the action’s authorization behavior. Verify its runtime checks; do not infer unrestricted access from the label.

      In every case

      A maintainer can act on attacker-authored content. Read-only execution does not eliminate token availability or secret disclosure through output.

      05 / KNOW THE BOUNDARY

      Useful signals.
      Explicit limits.

      Use Guard alongside source review and runtime controls. A supported clean scan is not proof of security.

      Possible paths, not exploits

      Severity reflects review priority over supported static semantics. It does not prove an attacker can execute a path.

      Coverage has edges

      Dynamic expressions, scripts and remote reusable workflow bodies can exceed the model. Read diagnostics before interpreting a result.

      Accuracy is unmeasured

      The 152-workflow development corpus supports reproducibility. Sealed human-labeled evaluation and measured precision/recall are not established.

      Version matters

      The reproduced case is pinned to a public scanner commit. Later source changes can alter findings; compare results against the same version.
